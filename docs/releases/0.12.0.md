# mzPeakJ 0.12.0

Changes since 0.11.1. The decision ids (D-1 … D-20, F-1 … F-5) are those of
[design-decisions.md](../design-decisions.md); [DESIGN.md](../../DESIGN.md) and [README.md](../../README.md) describe
the behaviour in detail.

## Upgrade notes

- **Chromatogram times are returned as stored.** Up to 0.11 the reader converted them to minutes. Code that relied
  on minutes calls `withTimeUnit("UO:0000031")`:
  `double[] minutes = tic.withTimeUnit("UO:0000031").time();`
- **`Chromatogram` has a 12th record component, `timeUnit`** (last). The old constructors still compile and give
  minute. Record equality, `hashCode` and `toString` include `timeUnit`. **Source incompatibility:** Java 21 record
  deconstruction patterns written against the 11 components (`case Chromatogram(var i, var id, ..., var precursors)`)
  no longer compile and need a 12th pattern component.
- **Stricter input.** Manifests that 0.11 read leniently may now be rejected, and so are an `ion_mobility_value`
  without `ion_mobility_type`, a format major version above 0 and implausible ZIP central directories (see
  [Now rejected](#now-rejected)).
- **Legacy (packed) spectra carry their summaries as Params.** A legacy spectrum now reads with the spectrum type and
  summary values (lowest and highest observed m/z, base peak m/z and intensity, total ion current) as Params, so a
  `SPLIT` write of a legacy dataset keeps the stored (float32 widened to double) summary values instead of deriving
  them from the arrays. See [Deviation](#deviation-d-9a).
- **The packed writer no longer repeats in the `parameters` list a term it writes as a column** (V-17): a spectrum
  type or summary Param goes to its column and leaves the list, and the type and summaries are derived only when the
  Params have none.
- **Build with the Maven Wrapper**: `./mvnw` (Maven 3.9.16). The build refuses an older Maven and fails when the
  repository filter for the EBI repository is not active.
- The converter jar runs with `java -jar mzpeakj-mzml-0.12.0-all.jar <in> <out>`.

## Security

- Jackson 2.23.0, parquet 1.18.2 (snappy-java 1.1.10.12, aircompressor 2.0.3, shaded Jackson 2.22.4), assertj 3.27.7
  (D-1). Enforcer floors fail the build on a downgrade to a vulnerable version.
- The EBI repository serves only jmzML's group ids (`uk.ac.ebi.jmzml`, `uk.ac.ebi.pride.architectural`,
  `psidev.psi.tools`); repositories declared in POMs are denied; the build fails closed when the filter is not
  active, and `tools/check-repo-policy.sh` checks the policy in CI (D-2). The checksums of every artifact the EBI
  repository serves (the jmzML jar and POM, the xxindex jar and POM, three pride parent POMs) are pinned.

## Build

- Maven Wrapper (`./mvnw`, Maven 3.9.16), also the build's minimum Maven version.
- The opt-in Python oracle environment of the mzML checks is pinned by a lock file (CPython 3.13.12, F-5).

## Converter jar

- `java [-Xmx...] -jar mzpeakj-mzml-0.12.0-all.jar [--help] [options] <input> <output>`: the jar has a `Main-Class`
  and `Enable-Native-Access: ALL-UNNAMED` (no "restricted method" warning on JDK 22 and newer) (D-3).
- Of fastutil it carries only the 81 class files jmzML needs: the jar is 44,727,561 bytes, against 61,438,477 bytes
  with the 10,653 fastutil classes before this change.
- An integration test (`ExecutableJarIT`) converts mzML to mzPeak and back with `java -jar`.

## Reader

New:

- `MzPeakReader.verifyIntegrity()` and `MzPeakReader.verifyIntegrity(Path)` check the members against the
  manifest's SHA-512 checksums and report per member (`IntegrityReport`) (D-16).
- `MzPeakReader.Options.withVersionCheck(boolean)` (or `-Dmzpeak.reader.ignoreVersion=true`) switches off the format
  version check (D-15).
- Datasets without spectrum metadata (chromatograms only) open with 0 spectra (D-15).
- ZIP archives with a duplicate member name resolve it to the last entry, with a warning (D-15; up to 0.11 it threw).
- Packed (legacy) spectra keep their unconsumed scalar columns as Params, as the split read of the same data does
  (D-9a).
- A column mapping whose unit is a column path gets its unit per row (string CURIE or `{cv_id, accession}` struct),
  for leftover Params and the collision energy (D-9b).
- Signal-file index keys stored as unsigned 32-bit integers of 2³¹ and above read correctly (F-1).
- Chromatograms carry their time unit (`Chromatogram.timeUnit()`, minute when the file declares none) and convert on
  request (`withTimeUnit`) (D-12).
- Faster metadata decoding (D-10): metadata columns are resolved once per member. On the 295,811-spectrum Orbitrap
  Astral DIA file (1.09 GB, OpenJDK 27.0.1, `-Xmx16g`, medians of interleaved runs), opening it and decoding all
  descriptions takes 2.23 s instead of 2.67 s in 0.11.1 (0.835×, bar 0.90×); the signal path is unchanged (0.996×);
  the decoded descriptions are identical.

### Now rejected

Each with a message naming the input, except the ZIP central directory check:

- Malformed manifests, as strictly as the Rust reader's serde (D-7): a missing required field, a field of the wrong
  JSON type, an accession or unit that is not CURIE-shaped, a known field given twice, or content after the JSON
  document.
- A manifest `metadata.version` with a major version above 0, unless the version check is off (D-15).
- An `ion_mobility_value` without (or with a blank) `ion_mobility_type` (D-8; up to 0.11 it read as drift time; the
  Rust reader panics there).
- A ZIP central directory whose size does not fit its entry count, or exceeds 64 MiB, zip64 and classic (F-2); its
  message gives the sizes, not the archive.
- A unit column path that names no column, or a struct unit column with a `cv_id` other than 1 (MS) or 2 (UO) (D-9b).

## Model and API

- `Chromatogram.timeUnit()` and `Chromatogram.withTimeUnit(String)`; `Chromatogram` record gains `timeUnit` as its
  last component (see [Upgrade notes](#upgrade-notes)).
- `IntegrityReport`, `MzPeakReader.verifyIntegrity()`, `MzPeakReader.verifyIntegrity(Path)`.
- `MzPeakReader.Options.withVersionCheck(boolean)`.

## Writer

- Chromatogram times are written as given, with their time unit declared; chromatograms of different time units in
  one dataset are refused before anything is written (D-12).
- `SPLIT` layout: scans and selected ions carry `ion_mobility_value` and `ion_mobility_type`; wavelength scans have
  the full scan schema; `chromatograms_metadata` carries `auxiliary_arrays` with its `ARROW:schema` entry (D-13).
  The split writer moves a scan's or selected ion's ion mobility Param into these columns when the reader rebuilds it
  (the scope's only ion mobility type, a finite number in the unit the reader gives that type), so the `parameters`
  list no longer holds it (the reference writer keeps it there too). It reads back, and is converted to mzML, after
  the remaining Params and with the name the reader gives its type: MS:1002815 as 'inverse reduced ion mobility
  drift time'.
- No dangling references in written footers: a run default or software reference that names nothing gets a stub
  entity of that id, with a WARNING each; diaPASEF.ref and diaPASEF.grid gain a stub instrument configuration 1
  (D-17).
- The packed writer treats the spectrum type and summaries as the split writer does (V-17, see
  [Upgrade notes](#upgrade-notes)).
- The Numpress encoder rejects non-finite m/z or intensity values and negative SLOF/PIC intensities, naming the
  spectrum, before anything is written (D-11).
- `ContentDigest` renders locale-independently and manifests use LF line ends (F-4).

### Deviation (D-9a)

A `SPLIT` write of a legacy (packed) dataset keeps the stored summary values instead of deriving them from the
arrays, because the reader now gives them as Params. This reverses the round's "keep as is" default "a split round
trip of a legacy file derives summary values"; keeping the derivation would have contradicted D-9 or needed a
provenance flag in the public model. A spectrum whose Params hold none of the five summaries still gets derived
values. Pinned by `SplitWriterPromotionTest.legacySplitWritePromotesStoredSummaries`; open for the maintainer to
confirm or overrule.

## Converter (mzpeakj-mzml)

- Chromatogram time units are kept (D-12c). A chromatogram whose unit differs from the first chromatogram's is
  converted to that unit and counted in a B-15 line (B-15 narrower). Otherwise unchanged (jmzML as is, D-19).

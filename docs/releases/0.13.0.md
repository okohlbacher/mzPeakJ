# mzPeakJ 0.13.0

Changes since 0.12.0: the spec-conformance round against the mzPeak specification at `963d64a`. The item ids (C1 …
C7 reading, R1 … R9 reading, W1 … W14 writing) and the decisions D13-1 … D13-27 are those of the round's design
(D13-28 was added by its final fix-up and decided by the maintainer);
[design-decisions.md](../design-decisions.md) lists them all with their reasons, and
[DESIGN.md](../../DESIGN.md) and [README.md](../../README.md) describe the behaviour in detail. What this round leaves
open, and what it kept out of scope, is listed at the end: [Still open](#still-open), [Out of scope](#out-of-scope).

Checked against the HUPO-PSI mzPeak specification at commit `963d64a04244ebc543532b5141c6e6103aa1f05a`
([HUPO-PSI/mzPeak-specification](https://github.com/HUPO-PSI/mzPeak-specification), 2026-11-21, "revise signing
process"), whose JSON schemas the tests copy (`mzpeakj/src/test/resources/spec-schema/SOURCE.txt`). Written files
were checked with the Rust reference reader of mzPeak-reference `2ee2589` (`mzpeak_prototyping` from
[HUPO-PSI/mzPeak](https://github.com/HUPO-PSI/mzPeak) at `2ee2589facddea6de6c1e7c6cfa77e56895420ec`, built as
[`tools/rdump`](../../tools/rdump/README.md), `RustReaderAcceptanceTest`) and with the HEAD Python reader
(`UpstreamInteropTest`).

## Upgrade notes

- **Chromatogram times are written in minutes** (W3, D13-1). The writer converts second, millisecond and hour once
  and refuses any other unit, naming the chromatogram and listing the supported units; chromatograms of one write no
  longer need to share a unit. Reading is unchanged: the stored values with their declared unit, which for a
  conformant file is minutes.
- **Rejected on write**, before anything is written and naming the entity:
  - a CURIE whose CV prefix `metadata.cv_list` would not declare (param accessions and CURIE-shaped units, extra-array
    keys, chromatogram types, intensity units; a param unit that is not a CURIE, such as `seconds`, is written as
    given in the file metadata, the scan settings and the `PACKED` layout, D13-26);
  - in the `SPLIT` layout, a param accession or unit that is neither null nor a CURIE the Rust reference reader
    parses, `PREFIX:number` with a number up to 4294967295 (such as the unit `seconds`, the accession `MS:abc` or an
    NCIT term such as `NCIT:C25330`), in the params of a spectrum, its scans and precursors (isolation windows,
    activations, selected ions), a chromatogram and its precursors, a wavelength spectrum and its scans (X-40,
    D13-28): the message names the entity, its index, the param's position and the field. That reader panics on such
    a value ([upstream-issues.md](../upstream-issues.md) R-16). Give `UO:0000010`, not `seconds`;
  - an explicit reference that names nothing the file metadata declares: a scan's instrument configuration, a
    spectrum's or chromatogram's data processing, the software of an instrument configuration or processing method, a
    scan setting's source file, a non-null run default (W12, D13-6, D13-9). **Without file metadata
    (`FileMetadata.EMPTY` or `null`) nothing is declared**, so the overloads without file metadata refuse every such
    reference too; write the spectra a reader returns with the file metadata it returns;
  - an intensity unit of a spectrum, its peaks or a chromatogram, or a session's spectrum intensity unit, that is not
    a CURIE (such as `percent`): it becomes an array unit of the array index, which `array_index.json` requires to be a
    CURIE;
  - a NaN m/z, time, wavelength or intensity (W10, D13-14; also in the converter);
  - a param value of a type mzPeak cannot write (W2, D13-16);
  - an auxiliary array that the Rust reference reader would panic on (X-32, D13-28, see [Decisions](#decisions)), in
    either layout: a name without an accession or with one outside the binary data array types that reader maps
    (MS:1002478, mean charge array, is one it does not), a data type or compression outside its tables, and a unit, a
    name unit, a param accession or a param unit that is not `PREFIX:number` with a number that fits u32 (such as
    `seconds`);
  - an uncompressed (MS:1000576) auxiliary array of a fixed-width data type (float32, float64, int32, int64) whose
    bytes are not its items times the width, which `AuxiliaryArray.doubles()` could not read back; compressed and
    string arrays are written as given (D13-19);
  - a spectrum in an intensity unit a session did not declare (`Options.withSpectrumIntensityUnits`, R5, D13-20);
  - an unknown CV given to `Options.withCvList` without version or at a moving URI (W8, D13-15);
  - in the `SPLIT` layout, a wavelength spectrum scan with a spectrum reference, which the wavelength scan table has
    no column for (R8, D13-12). The scans of wavelength spectra are checked as those of spectra (CV prefixes,
    instrument configuration, param values) in both layouts.
- **diaPASEF.ref and diaPASEF.grid** (the upstream examples) name instrument configuration 1 as the run default but
  declare only configuration 0. Writing what the reader returns for them is now refused with
  `file metadata: run: default_instrument_configuration_id 1 names no instrument configuration (declared: 0); declare
  the configuration in FileMetadata.instrumentConfigurations or set MsRun.defaultInstrumentId to a declared one`. Fix
  it by adding the configuration (as the tests do with `Fixtures.withDeclaredDefaults`, a configuration of id 1
  without components) or by setting the run default to 0. The `ExtractSpectra` example, which writes the file
  metadata it reads, therefore refuses both files: it prints that message, without a stack trace, and exits with
  status 1.
- **Rejected on read**: a ZIP member that is not STORED or is encrypted (R9, D13-3); a parameter without `name`
  (C6); an unpaired interior null in a null-marked array, per chunk row for chunked data (R2, D13-13); a delta chunk
  row with points but without `chunk_start` (a missing column or a null cell), which decoded from 0 and invented its
  axis values.
- **Now read**: every Parquet codec (C1); empty row groups (C3); chunked chromatograms in every encoding (C4) and
  chunked wavelength spectra (C5); SLOF/PIC intensity next to any axis encoding (R3); column mappings without
  `accession` and params without `accession` or `unit` (C6); unsigned integer signal columns (R4).
- **Model and API additions.** New record components, so Java 21 record deconstruction patterns written against
  the 0.12.0 components need updating; the old constructors stay:
  `Chromatogram.products`, `Chromatogram.auxiliaryArrays`; `WavelengthSpectrum.scans`,
  `WavelengthSpectrum.auxiliaryArrays`; `SpectrumDescription.dataProcessingRef`, `SpectrumDescription.products`;
  `Precursor.msLevel`. New: `Spectrum.intensityUnit()`, `Spectrum.peakIntensityUnit()`,
  `Spectrum.auxiliaryArrays()` with new constructors; the types `AuxiliaryArray` and
  `Product(precursorIndex, productIndex, isolationWindow, parameters)`; `IntegrityReport.Status.REJECTED_MEMBER` and
  `IntegrityReport.MemberResult.reason()` (5th component); `MzPeakWriter.Options.withSpectrumIntensityUnits`;
  `PureJavaCodecFactory`. `ZstdCompressionCodecFactory` is deprecated, not removed.
- **Values that read differently.** `SelectedIon.mz()` may be NaN (a selected ion without m/z is kept, R7,
  D13-22). A JSON array param value reads as its compact JSON text, so a JSON array in footer or manifest metadata
  comes back as a JSON string when written again (C7, D13-17). Null-marked m/z are filled by the spec's rule, per
  chunk (R2, D13-13): small differences in filled points. On the fixtures where the Rust and the Python reference
  readers agree, mzPeakJ now agrees with both; on Example_Processed.img it follows the spec's null-fill rule, as the
  Python reader does, while the Rust reader's fill differs from it by up to 6.1e-5 at 10 to 26 points per spectrum.
- **Written names follow the spec; the old names are still read** (D13-7): the chromatogram data processing column
  is `data_processing_id`, was `data_processing_ref` (W4); scan settings write `source_file_references` and each
  target as an object with its `parameters`, were `source_file_refs` and bare param arrays (W5); the wavelength
  representation column is `opt_spectrum_representation`, was `spectrum_representation`, and the wavelength scans no
  longer have `ion_mobility_value`, `ion_mobility_type` and `spectrum_reference` columns (W11, D13-12); their scan
  window limits are FLOAT (float32) mapped in nanometers (UO:0000018), were DOUBLE mapped in m/z (R8, D13-24). The split
  run key is `default_instrument_configuration_id` (W1). The packed layout keeps its pin-era names (D13-11).
- **Wavelength spectra read back differently after a split write** (W11): the terms written as columns (the spectrum
  type MS:1000804, the representation, the observed wavelength range, base peak intensity, total ion current) no
  longer stay in the `parameters` list as well, so they read back after the other params, in column order, and the
  term-marker ones without a name (`Param(null, "MS:1000804", null, null)`).
- **Derived base peak intensity and total ion current only of detector counts.** Their columns are in MS:1000131, so
  the writer derives them only when the spectrum's intensity unit is MS:1000131 or not given; a spectrum in another
  unit, such as MS:1000132, is written without them (the m/z-derived summaries stay).
- **A new WARNING** when a write drops components the reader returns but the writer does not write yet (see
  [Out of scope](#out-of-scope)), for example `mzPeakJ reads but does not write yet: the products of 2 spectra and 1
  chromatogram; the MS level of 1 precursor`. The bytes written are unchanged.
- **Wavelength scans are written** (R8, D13-24): the `SPLIT` layout writes the scans of a wavelength spectrum as
  given, the scan window limits rounded to float32, and one scan holding the spectrum time for one without scans, as
  before. The `PACKED` layout writes none and warns once with the counts, such as `1 wavelength spectrum carries scans
  (2 in all), which the packed metadata layout does not write`.
- **Wavelength scan windows are read in nanometers** (R8, D13-24): the reader takes their unit from the column
  mapping (the scan table's nanometer when none is mapped). Nanometer or no unit reads as stored; micrometer
  (UO:0000017), millimeter (UO:0000016) and meter (UO:0000008) are converted; any other unit, or a unit column, fails
  the read with a message naming the member and the column, once a window holds a value. This includes the m/z
  (MS:1000040) that the reference writer maps, as in has_uv, whose wavelength scans hold no windows and read as
  before. Spectrum scan windows read as before.
- **Split output declares the fields the spec requires as required** (W14, X-37, D13-27): the item, value and name of
  every metadata-table `parameters` list, and the auxiliary-array name, name.name, data_type, compression and items.
  The `parameters` list inside an auxiliary array keeps optional item fields (as auxiliary-arrays.md shows it;
  metadata-tables.md disagrees). `PACKED` output is unchanged. Readers, mzPeakJ's and the reference ones, read the
  files as before.
- **`PACKED` checks what it drops.** A `PACKED` write runs the checks of the auxiliary arrays and of the wavelength
  scans (CV prefixes, references, param values, the auxiliary-array rules of D13-28) and declares their CV prefixes in
  `metadata.cv_list`, although it writes neither, as it already checks the Params it drops. These are the checks
  common to both layouts; the split-only ones, the param-CURIE check of D13-28 and the refusal of a wavelength scan
  with a spectrum reference (D13-12), are not run.

## Decisions

The maintainer's defaults for this round, applied as given, the round's defaults that replace earlier decisions
(D13-13) and the one deviation kept for confirmation (D13-10). The other defaults of the round, D13-8, D13-11,
D13-12 and D13-14 to D13-27, are listed in
[design-decisions.md](../design-decisions.md#2026-11-22-and-2026-11-23-decisions-for-0130).

- **D13-1, W3 overrides decision D-12 in part**: chromatogram times are written in minutes; `Chromatogram.timeUnit`
  stays, the reader is unchanged, and the rule that all chromatograms of one write share a unit goes. The converter
  drops its own normalisation.
- **D13-2, C6 refines decision D-7**: manifest parsing stays strict for wrong types, schema-required fields and
  values outside a closed enum, and accepts fields the JSON schema makes optional; a param `unit` is any string or
  null.
- **D13-3, R9**: a ZIP member stored with another method than STORED, or with the encryption bit set, is rejected
  with a message naming the member (D13-23: when it is read; `verifyIntegrity` reports it as `REJECTED_MEMBER`).
- **D13-4, C1**: every Parquet codec is read; all but ZSTD (still `zstd-jni`, native, as before) with pure-JVM
  code: GZIP with `java.util.zip`; SNAPPY, LZ4, LZ4_RAW and LZO with `io.airlift:aircompressor` 2.0.3 (Apache
  License 2.0, now a direct dependency); BROTLI with
  `org.brotli:dec` 0.1.2 (MIT License, [licenses/MIT-brotli.txt](../../licenses/MIT-brotli.txt), listed in
  [NOTICE](../../NOTICE)). The writer keeps ZSTD. OSV listed no advisory for either (2026-11-22).
- **D13-5, C2**: the first array-index entry with `buffer_format: index` and `array_type: MS:1003870` is the entity
  key; another index entry (such as a parallel time index) is never the key.
- **D13-6 and D13-9, W12**: undeclared CV prefixes and dangling references are rejected by the writer, which
  replaces the decision "the writer warns on unknown CURIE prefixes" and the stub part of D-17. A null run default is
  still filled (the first declared entry, else a stub with a WARNING). Consequence: diaPASEF.ref and diaPASEF.grid
  as read are refused (see [Upgrade notes](#upgrade-notes) for the fix).
- **D13-7, W4, W5, W11**: written names follow the spec; the reader keeps reading the old ones.
- **D13-13, R2 overrides "null-pair fill keeps mzPeakJ's rule (Q-U4)"**: null-marked m/z (and chunked chromatogram
  times) are filled by the spec's rule (signal-data.md, Decoding null pairs), per chunk row in the chunked and
  Numpress layouts and per spectrum in the point layout; an unpaired null between stored values is refused. The
  trade-off: on small the median error of a filled m/z against the mzML rises from about 3.9e-9 to about 9.8e-8, and
  mzPeakJ agrees with the HEAD Python reader (with the Rust reader too, except on Example_Processed.img, R-6).
- **D13-28, the maintainer's default** (X-32, X-40): the writer refuses what the Rust reference reader panics on
  (mzPeak-reference `2ee2589`, `src/reader/visitor.rs:1896-1922` and `curie_array_visitor.rs:34,70,257`;
  [upstream-issues.md](../upstream-issues.md) R-15, R-16). In every layout, an auxiliary array's name accession, data
  type or compression outside mzdata's `ArrayType`, `BinaryDataArrayType` and `BinaryCompressionType` tables, and a
  unit or param accession of it that is not `PREFIX:number` (u32); in the `SPLIT` layout also the accession and unit
  of every param of a spectrum, scan, precursor, selected ion, chromatogram, wavelength spectrum and wavelength scan
  that is neither null nor `PREFIX:number` (u32). This deviates from D13-19, by which the writer writes an
  array's data unchanged, and replaces D13-26 ("a unit that is not a CURIE is written as given") for the split
  layout's param lists; D13-26 still holds for the file metadata, the scan settings and the `PACKED` layout, which the
  Rust reader does not parse.
- **D13-10, kept for the maintainer's confirmation**: the writer keeps renumbering entities 0..n-1 (no index gaps
  are written) and keeps writing a `precursor_index` that names no written spectrum as null with its `precursor_id`,
  instead of rejecting both as the W12 default says; rejecting them would break writing a subset of what the reader
  returns, such as the MS2 spectra of small.

## Reading

- C1 Parquet codecs, C2 entity key by array type, C3 empty row groups, C4 chunked chromatograms (all encodings,
  through the spectrum chunk decoder), C5 chunked wavelength spectra, C6 optional manifest fields, C7 JSON array and
  list-column param values.
- R1 auxiliary arrays (`AuxiliaryArray`: the bytes as stored, `doubles()` decompresses none and zlib on demand; zlib is
  inflated only up to the declared size and one byte more), R2 null-pair fill by the spec's rule, R3 secondary
  Numpress intensity, R4 unsigned integer intensities, R5 spectrum intensity units, R6 spectrum data processing,
  precursor MS level and products, R7 selected ions without m/z, R8 wavelength scans with nanometer windows, R9 ZIP
  member checks.
- A delta chunk row with points and no `chunk_start` is refused, naming the entity; until this release it decoded
  from 0 (for chromatograms since C4).
- A spectrum chunk row that cannot be decoded fails only its own spectrum, with the same message: the other spectra
  of its row group read, where until this release each of them threw the message naming the bad spectrum.
- On JDK 24 and later, the first SNAPPY, LZ4, LZ4_RAW or LZO page read makes the JVM print its one-time
  `sun.misc.Unsafe` warning about aircompressor 2.0.3 (`--sun-misc-unsafe-memory-access=allow` turns it off).
  aircompressor 3.x no longer uses `sun.misc.Unsafe` but needs Java 22, and mzPeakJ targets Java 17.

## Writing

- W1 run key `default_instrument_configuration_id` and spec schemas at `963d64a`; W2 every param value type; W3
  chromatogram times in minutes; W4 chromatogram `data_processing_id`; W5 scan settings in the spec's JSON shape; W6
  `buffer_priority` per logical array; W7 the MSn selected-ion chain is replicated; W8 fixed-release CV URIs; W10 no
  NaN in written columns; W11 wavelength columns without duplicates, `opt_` names; W12 writer validation (above); W14
  required item fields of `parameters` and `auxiliary_arrays` in the split layout (above).
- R1: the split layout writes the auxiliary arrays of spectra, chromatograms and wavelength spectra, their bytes and
  compression as given, refused where D13-28 says.
- D13-28 for the split layout's param lists (X-40): checked in batch writes and in sessions, before anything is
  written; the file metadata and the scan settings, written as JSON, are not affected.
- **W9: Numpress chunk bounds are the decoded values.** `mz_chunk_start` and `mz_chunk_end` of a Numpress chunk are
  now the first and last values decoded from the stored linear payload, as `chunked-layout.md` defines them
  (inclusive first and last value), no longer the raw input m/z, which the Rust reference writer still writes.
- R5: `spectra_data` and `spectra_peaks` hold the intensities of each spectrum intensity unit in a column of their
  own; a session declares the units when it opens.
- R6: the spectrum `data_processing_id` is written by the split layout.
- R8: the split layout writes the scans of wavelength spectra, their windows FLOAT in nanometers (above).
- The rejection messages of an unknown chromatogram time unit and of an undeclared run default say how to fix them.
- A `Session` checks a chromatogram or wavelength spectrum when it is added, as it checks a spectrum: its Params, NaN
  values, a negative precursor index and, in the `SPLIT` layout, a wavelength scan with a spectrum reference are
  refused by `addChromatogram` or `addWavelengthSpectrum`, with the batch write's message, and the entity is not
  added, so the session goes on; until this release they failed `finish()`. Index rules (non-negative, unique) are
  still checked at the finish, and so are these checks again: an entity keeps the caller's arrays and Params, so a
  value changed after it was added (a NaN time, say) still fails `finish()`, which then leaves nothing.

## Converter (mzpeakj-mzml)

- **The B-15 line about chromatogram times is gone** (W3): the converter hands each chromatogram over in its own
  time unit and the mzPeak writer stores minutes, so mzML → mzPeak → mzML gives minutes. B-15 still counts scan start
  times converted to minutes and drift-time arrays converted to milliseconds.
- An mzML NaN in an axis or intensity array fails the conversion with the writer's message (W10).
- The mzML cv list goes to the writer as far as `Options.withCvList` accepts it (W8).
- Selected ions without m/z (R7) and the spectrum data processing (R6) are converted.
- **Spectrum intensity units are kept** (R5, X-36): the mzML converter keeps the intensity unit of MS spectra
  (MS:1000131 number of detector counts, MS:1000132 percent of base peak, MS:1000814 counts per second) both ways and
  declares the units it finds to the mzPeak session, so mzML files with several intensity units convert; other units
  are still rejected. A spectrum without points in a unit other than MS:1000131 comes back in MS:1000131 (B-36). The
  fixed line A-13 (array units and data types as stored in mzPeak) now names only the other arrays.
- **Wavelength scans are kept** (R8, X-36): wavelength (EMR) spectra keep their scans both ways, scan windows in
  nanometers (UO:0000018); only precursors and scan spectrum references of wavelength spectra are lost (B-23). A
  wavelength spectrum without scans is written to mzML with one scan holding its time (A-8), and a time other than
  the first scan's start time is lost (A-9).
- With the default `split` layout, an mzML cvParam of a spectrum, scan, precursor, selected ion, chromatogram or
  wavelength spectrum whose accession or unit accession is not `PREFIX:number` (such as an NCIT term) fails the
  conversion with the writer's message (D13-28, X-40); `--layout packed` writes it in the param lists that layout
  writes and drops chromatogram and wavelength-spectrum Params and wavelength scans with a WARNING.
- **Arrays of another length are auxiliary arrays** (R1, X-35): an mzML binary data array whose declared length
  differs from its axis array's is kept as an auxiliary array (64-bit floats, no compression, its array type or
  non-standard name and its declared unit kept, its values not converted) instead of dropped; only an array type the
  Rust reference reader does not map is still dropped (B-43). mzPeak → mzML writes every auxiliary array as a
  binaryDataArray with its own `arrayLength`; its params, data processing and a unit of a CV the cv list lacks are not
  written (A-34), and one whose compression or data type cannot be decoded is dropped (A-35). A-14 is withdrawn.

  SNAPPY, LZ4, LZ4_RAW and LZO codecs on read (C1, D13-4); it was already on the classpath through parquet-hadoop,

- New: `org.brotli:dec` 0.1.2 (MIT License, [licenses/MIT-brotli.txt](../../licenses/MIT-brotli.txt), listed in

- Both come from Maven Central and load no native code; OSV listed no advisory for either (2026-11-22). ZSTD stays
  with `zstd-jni`, as before. No other dependency version changed.

## Known issues of the references


- The Rust reference reader (`tools/rdump`, `mzpeak_prototyping` at `2ee2589`) reads every split output of the
  acceptance test; [upstream-issues.md](../upstream-issues.md) records the new losses: R-10 (a null extra cell reads
  as 0.0; mzPeakJ writes a NaN extra cell as null for W10), R-11 (the range read projects only the first intensity
  column) and R-12 (in the Numpress layout, a per-unit intensity is labelled `DetectorCounts`, and the range read
  panics with "list array"; R-12 is not asserted by the test yet). Of the auxiliary arrays mzPeakJ now writes, the
  Rust reader cannot decode a compressed one (R-13) and drops those of a chunked spectrum spanning row groups (R-14)
  and of a spectrum without data points (R-17); it panics on the arrays and params that D13-28 refuses (R-15, R-16).
  R-6 changes: mzPeakJ's null fill now follows the spec, and the Rust reader's differs from it on
  Example_Processed.img only.
- The required item fields of W14 are read by the Rust reference reader and the HEAD Python reader as the optional
  ones were (`RustReaderAcceptanceTest`, `UpstreamInteropTest`).
- A latent difference (W5): the reference's `ScanSettings` struct keeps the pin-era names that mzPeakJ no longer
  writes; neither reference reader parses `scan_settings_list`, so nothing breaks today.
- [upstream-issues.md](../upstream-issues.md#inconsistencies-in-the-specification) now also lists the inconsistencies
  in the specification found by the round, among them the optional item fields of an auxiliary array's `parameters`
  list against metadata-tables.md.

## Out of scope

Kept as they are in this round:

- **Writing the products and the precursor MS level** (D13-21): they are read only, since writing products would make
  the Rust reference reader panic; a write that drops them warns once with the counts.
- **The `PACKED` layout** (W13): its pin-era dialect stays frozen (D13-11). It writes no auxiliary arrays and no
  wavelength scans and warns, and the HEAD readers do not read it.
- **The legacy packed wavelength scans** are not read (D13-24): a legacy packed wavelength spectrum reads without
  scans.
- **Imaging naming and the IMS CV URI** (D-14): imaging output keeps following the Rust reference.
- **zstd-jni**, which loads native code for ZSTD, and the minor items of the conformance audit.

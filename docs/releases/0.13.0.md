# mzPeakJ 0.13.0

Changes since 0.12.0: the spec-conformance round against the mzPeak specification at `963d64a`. The item ids (C1 …
C7 reading, R1 … R9 reading, W1 … W14 writing) and the decisions D13-1 … D13-27 are those of the round's design;
[design-decisions.md](../design-decisions.md) keeps the ones that still shape the code, and
[DESIGN.md](../../DESIGN.md) and [README.md](../../README.md) describe the behaviour in detail. Not every item of the
round is in this release: see [Still open](#still-open).

## Upgrade notes

- **Chromatogram times are written in minutes** (W3, D13-1). The writer converts second, millisecond and hour once
  and refuses any other unit, naming the chromatogram and listing the supported units; chromatograms of one write no
  longer need to share a unit. Reading is unchanged: the stored values with their declared unit, which for a
  conformant file is minutes.
- **Rejected on write**, before anything is written and naming the entity:
  - a CURIE whose CV prefix `metadata.cv_list` would not declare (param accessions and CURIE-shaped units, extra-array
    keys, chromatogram types, intensity units; a param unit that is not a CURIE, such as `seconds`, is written as
    given, D13-26);
  - an explicit reference that names nothing the file metadata declares: a scan's instrument configuration, a
    spectrum's or chromatogram's data processing, the software of an instrument configuration or processing method, a
    scan setting's source file, a non-null run default (W12, D13-6, D13-9). **Without file metadata
    (`FileMetadata.EMPTY` or `null`) nothing is declared**, so the overloads without file metadata refuse every such
    reference too; write the spectra a reader returns with the file metadata it returns;
  - an intensity unit of a spectrum, its peaks or a chromatogram, or a session's spectrum intensity unit, that is not
    a CURIE (such as `percent`): it becomes an array unit of the array index, which `array_index.json` requires to be a
    CURIE;
  - a NaN m/z, time, wavelength or intensity (W10, D13-14; also in the converter);
  - a param value of a type mzPeak cannot write (W2, D13-16);
  - a spectrum in an intensity unit a session did not declare (`Options.withSpectrumIntensityUnits`, R5, D13-20);
  - an unknown CV given to `Options.withCvList` without version or at a moving URI (W8, D13-15);
  - in the `SPLIT` layout, a wavelength spectrum scan with a spectrum reference, which the wavelength scan table has
    no column for (R8, D13-12). The scans of wavelength spectra are checked as those of spectra (CV prefixes,
    instrument configuration, param values) in both layouts.
- **diaPASEF.ref and diaPASEF.grid** (the upstream examples) name instrument configuration 1 as the run default but
  declare only configuration 0. Writing what the reader returns for them is now refused with
  `file metadata: run: default_instrument_configuration_id 1 names no instrument configuration (declared: 0); declare
  the configuration in FileMetadata.instrumentConfigurations or set MsRun.defaultInstrumentId to a declared one`. Fix
  it by adding the configuration (as the tests do with `Fixtures.withDeclaredDefaults`, a configuration of id 1
  without components) or by setting the run default to 0.
- **Rejected on read**: a ZIP member that is not STORED or is encrypted (R9, D13-3); a parameter without `name`
  (C6); an unpaired interior null in a null-marked array, per chunk row for chunked data (R2, D13-13); a delta chunk
  row with points but without `chunk_start` (a missing column or a null cell), which decoded from 0 and invented its
  axis values.
- **Now read**: every Parquet codec (C1); empty row groups (C3); chunked chromatograms in every encoding (C4) and
  chunked wavelength spectra (C5); SLOF/PIC intensity next to any axis encoding (R3); column mappings without
  `accession` and params without `accession` or `unit` (C6); unsigned integer signal columns (R4).
- **Model and API additions.** New record components, so Java 21 record deconstruction patterns written against
  the 0.12.0 components need updating; the old constructors stay:
  `Chromatogram.products`, `Chromatogram.auxiliaryArrays`; `WavelengthSpectrum.scans`,
  `WavelengthSpectrum.auxiliaryArrays`; `SpectrumDescription.dataProcessingRef`, `SpectrumDescription.products`;
  `Precursor.msLevel`. New: `Spectrum.intensityUnit()`, `Spectrum.peakIntensityUnit()`,
  `Spectrum.auxiliaryArrays()` with new constructors; the types `AuxiliaryArray` and
  `Product(precursorIndex, productIndex, isolationWindow, parameters)`; `IntegrityReport.Status.REJECTED_MEMBER` and
  `IntegrityReport.MemberResult.reason()` (5th component); `MzPeakWriter.Options.withSpectrumIntensityUnits`;
  `PureJavaCodecFactory`. `ZstdCompressionCodecFactory` is deprecated, not removed.
- **Values that read differently.** `SelectedIon.mz()` may be NaN (a selected ion without m/z is kept, R7,
  D13-22). A JSON array param value reads as its compact JSON text, so a JSON array in footer or manifest metadata
  comes back as a JSON string when written again (C7, D13-17). Null-marked m/z are filled by the spec's rule, per
  chunk (R2, D13-13): small differences in filled points, and mzPeakJ now agrees with both references.
- **Written names follow the spec; the old names are still read** (D13-7): the chromatogram data processing column
  is `data_processing_id`, was `data_processing_ref` (W4); scan settings write `source_file_references` and each
  target as an object with its `parameters`, were `source_file_refs` and bare param arrays (W5); the wavelength
  representation column is `opt_spectrum_representation`, was `spectrum_representation`, and the wavelength scans no
  longer have `ion_mobility_value`, `ion_mobility_type` and `spectrum_reference` columns (W11, D13-12); their scan
  window limits are FLOAT (float32) mapped in nanometers (UO:0000018), were DOUBLE mapped in m/z (R8, D13-24). The split
  run key is `default_instrument_configuration_id` (W1). The packed layout keeps its pin-era names (D13-11).
- **Wavelength spectra read back differently after a split write** (W11): the terms written as columns (the spectrum
  type MS:1000804, the representation, the observed wavelength range, base peak intensity, total ion current) no
  longer stay in the `parameters` list as well, so they read back after the other params, in column order, and the
  term-marker ones without a name (`Param(null, "MS:1000804", null, null)`).
- **Derived base peak intensity and total ion current only of detector counts.** Their columns are in MS:1000131, so
  the writer derives them only when the spectrum's intensity unit is MS:1000131 or not given; a spectrum in another
  unit, such as MS:1000132, is written without them (the m/z-derived summaries stay).
- **A new WARNING** when a write drops components the reader returns but the writer does not write yet (see
  [Still open](#still-open)), for example `mzPeakJ reads but does not write yet: the products of 2 spectra and 1
  chromatogram; the MS level of 1 precursor`. The bytes written are unchanged.
- **Wavelength scans are written** (R8, D13-24): the `SPLIT` layout writes the scans of a wavelength spectrum as
  given, the scan window limits rounded to float32, and one scan holding the spectrum time for one without scans, as
  before. The `PACKED` layout writes none and warns once with the counts, such as `1 wavelength spectrum carries scans
  (2 in all), which the packed metadata layout does not write`.

## Decisions

The maintainer's defaults for this round, applied as given:

- **D13-1, W3 overrides decision D-12 in part**: chromatogram times are written in minutes; `Chromatogram.timeUnit`
  stays, the reader is unchanged, and the rule that all chromatograms of one write share a unit goes. The converter
  drops its own normalisation.
- **D13-2, C6 refines decision D-7**: manifest parsing stays strict for wrong types, schema-required fields and
  values outside a closed enum, and accepts fields the JSON schema makes optional; a param `unit` is any string or
  null.
- **D13-3, R9**: a ZIP member stored with another method than STORED, or with the encryption bit set, is rejected
  with a message naming the member (D13-23: when it is read; `verifyIntegrity` reports it as `REJECTED_MEMBER`).
- **D13-4, C1**: every Parquet codec is read with pure-JVM code: GZIP with `java.util.zip`; SNAPPY, LZ4, LZ4_RAW and
  LZO with `io.airlift:aircompressor` 2.0.3 (Apache License 2.0, now a direct dependency); BROTLI with
  `org.brotli:dec` 0.1.2 (MIT License, [licenses/MIT-brotli.txt](../../licenses/MIT-brotli.txt), listed in
  [NOTICE](../../NOTICE)). The writer keeps ZSTD. OSV listed no advisory for either (2026-11-22).
- **D13-5, C2**: the first array-index entry with `buffer_format: index` and `array_type: MS:1003870` is the entity
  key; another index entry (such as a parallel time index) is never the key.
- **D13-6 and D13-9, W12**: undeclared CV prefixes and dangling references are rejected by the writer, which
  replaces the decision "the writer warns on unknown CURIE prefixes" and the stub part of D-17. A null run default is
  still filled (the first declared entry, else a stub with a WARNING). Consequence: diaPASEF.ref and diaPASEF.grid
  as read are refused (see [Upgrade notes](#upgrade-notes) for the fix).
- **D13-7, W4, W5, W11**: written names follow the spec; the reader keeps reading the old ones.
- **D13-10, kept for the maintainer's confirmation**: the writer keeps renumbering entities 0..n-1 (no index gaps
  are written) and keeps writing a `precursor_index` that names no written spectrum as null with its `precursor_id`,
  instead of rejecting both as the W12 default says; rejecting them would break writing a subset of what the reader
  returns, such as the MS2 spectra of small.

## Reading

- C1 Parquet codecs, C2 entity key by array type, C3 empty row groups, C4 chunked chromatograms (all encodings,
  through the spectrum chunk decoder), C5 chunked wavelength spectra, C6 optional manifest fields, C7 JSON array and
  list-column param values.
- R1 auxiliary arrays (`AuxiliaryArray`: the bytes as stored, `doubles()` decompresses none and zlib on demand; zlib is
  inflated only up to the declared size and one byte more), R2 null-pair fill by the spec's rule, R3 secondary
  Numpress intensity, R4 unsigned integer intensities, R5 spectrum intensity units, R6 spectrum data processing,
  precursor MS level and products, R7 selected ions without m/z, R8 wavelength scans with nanometer windows, R9 ZIP
  member checks.
- A delta chunk row with points and no `chunk_start` is refused, naming the entity; until this release it decoded
  from 0 (for chromatograms since C4).
- On JDK 24 and later, the first SNAPPY, LZ4, LZ4_RAW or LZO page read makes the JVM print its one-time
  `sun.misc.Unsafe` warning about aircompressor 2.0.3 (`--sun-misc-unsafe-memory-access=allow` turns it off).
  aircompressor 3.x no longer uses `sun.misc.Unsafe` but needs Java 22, and mzPeakJ targets Java 17.

## Writing

- W1 run key `default_instrument_configuration_id` and spec schemas at `963d64a`; W2 every param value type; W3
  chromatogram times in minutes; W4 chromatogram `data_processing_id`; W5 scan settings in the spec's JSON shape; W6
  `buffer_priority` per logical array; W7 the MSn selected-ion chain is replicated; W8 fixed-release CV URIs; W10 no
  NaN in written columns; W11 wavelength columns without duplicates, `opt_` names; W12 writer validation (above).
- **W9: Numpress chunk bounds are the decoded values.** `mz_chunk_start` and `mz_chunk_end` of a Numpress chunk are
  now the first and last values decoded from the stored linear payload, as `chunked-layout.md` defines them
  (inclusive first and last value), no longer the raw input m/z, which the Rust reference writer still writes.
- R5: `spectra_data` and `spectra_peaks` hold the intensities of each spectrum intensity unit in a column of their
  own; a session declares the units when it opens.
- R6: the spectrum `data_processing_id` is written by the split layout.
- R8: the split layout writes the scans of wavelength spectra, their windows FLOAT in nanometers (above).
- The rejection messages of an unknown chromatogram time unit and of an undeclared run default say how to fix them.

## Converter (mzpeakj-mzml)

- **The B-15 line about chromatogram times is gone** (W3): the converter hands each chromatogram over in its own
  time unit and the mzPeak writer stores minutes, so mzML → mzPeak → mzML gives minutes. B-15 still counts scan start
  times converted to minutes and drift-time arrays converted to milliseconds.
- An mzML NaN in an axis or intensity array fails the conversion with the writer's message (W10).
- The mzML cv list goes to the writer as far as `Options.withCvList` accepts it (W8).
- Selected ions without m/z (R7) and the spectrum data processing (R6) are converted.
- The fixed lines A-13 (array units and data types as stored in mzPeak) and A-14 (auxiliary arrays) now say that the
  converter does not use them yet; the library reads the spectrum intensity units and the auxiliary arrays.

## Interop

- The Rust reference reader (`tools/rdump`, `mzpeak_prototyping` at `2ee2589`) reads every split output of the
  acceptance test; [upstream-issues.md](../upstream-issues.md) records the new losses: R-10 (a null extra cell reads
  as 0.0; mzPeakJ writes a NaN extra cell as null for W10), R-11 (the range read projects only the first intensity
  column) and R-12 (in the Numpress layout, a per-unit intensity is labelled `DetectorCounts`, and the range read
  panics with "list array"; R-12 is not asserted by the test yet).

## Still open

Not in this release, because their units were blocked or depend on a blocked unit:

- **Products and the precursor MS level** stay read only (D13-21): a write that drops them warns once with the
  counts. R1 writing (X-32) and R8 writing (X-34) landed: the `SPLIT` layout writes the auxiliary arrays of spectra,
  chromatograms and wavelength spectra, their bytes and compression as given, and the scans of wavelength spectra;
  `PACKED` writes neither and warns.
- **The converter half of R1, R5 and R8 (X-35, X-36)**: mzML arrays of a different length are not converted to
  auxiliary arrays, spectrum intensity units other than MS:1000131 are not converted, and wavelength scans are not
  converted.
- **W14 (X-37)**: the required fields of the parameters and auxiliary-array items (D13-27) are still written
  optional.
- Not done in this round: the second half of the null `chunk_start` finding (an intensity list one shorter than the
  values paired one-to-one), and a corpus sweep of the forward-backward round trip (no corpus at hand; NaN-m/z write
  refusals are now classified as a known limit there).

The version is not bumped yet: the maintainer decides whether to release with X-32 to X-39 open.
